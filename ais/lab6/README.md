# Лабораторная 6. Логистическая регрессия с нуля

Реализация бинарной логистической регрессии **с нуля** (только NumPy и Pandas) для датасета **Pima Indians Diabetes**. Задача — предсказать наличие диабета (`1`) или его отсутствие (`0`) по 8 медицинским признакам.

## Структура проекта

```text
├── main.py                 # точка входа, весь сценарий эксперимента
├── preprocessing.py        # загрузка, обработка нулей, split, стандартизация
├── logistic_regression.py  # sigmoid, log loss, градиент, Гессиан, GD и Ньютон
├── metrics.py              # accuracy, precision, recall, F1
├── stats_plots.py          # разведочные графики
├── experiments.py          # grid search и исследования гиперпараметров
├── diabetes.csv            # датасет
├── grid_results.csv        # результаты grid search (генерируется)
└── plots/                  # все графики (генерируются)
```

## Запуск

```bash
pip install numpy pandas matplotlib
python main.py
```

Всё воспроизводимо: использовался `random_state=42`, и делили датасет на тест и оубчение 80/20.

## Ключевые решения по данным

- **Нули → NaN.** В колонках `Glucose`, `BloodPressure`, `SkinThickness`, `Insulin`, `BMI` ноль физиологически невозможен — это замаскированные пропуски.
- **Порядок препроцессинга:** `fix_zeros -> split -> fill_median(train) -> standardize(train) -> add_bias`. Медиана и `mean`/`std` считаются **только по train** — защита от data leakage.
- **Стандартизация** обязательна: признаки разного масштаба (`Glucose` ~100, `BMI` ~30, `DiabetesPedigreeFunction` ~0.5). Без неё GD сходится плохо, а метод Ньютона нестабилен.
- **Bias** добавлен отдельным столбцом единиц последним — чтобы стандартизация его не обнулила.
- **`Pregnancies`** (число беременностей в анамнезе) **использовался** как обычный числовой признак — ни один столбец не исключался.

## Результаты

### Learning rate (GD, 1000 итераций)

| `lr`  | Поведение                         | F1 (test)       |
|-------|-----------------------------------|-----------------|
| 0.001 | почти не сдвинулся — недообучение | низкий          |
| 0.01  | медленно, но сходится             | средний         |
| 0.05  | быстро, стабильно                 | **лучший**      |
| 0.1   | быстро, стабильно                 | **лучший**      |
| 0.5   | резкое падение, early stopping    | тот же, что 0.1 |

**Вывод:** рабочий диапазон `[0.05, 0.1]`. Значение `0.001` — потеря времени, `0.5` не даёт выигрыша в метриках и рискует вызвать осцилляции на плохо обусловленных данных.

### Число итераций (GD, lr=0.1)

- Accuracy и F1 **выходят на плато к ~500 итерациям**.
- Train loss продолжает медленно падать — это нормально: метрики классификации насыщаются раньше вероятностей.
- **Вывод:** 500–1000 итераций достаточно, 5000 — избыточно.

### GD vs Newton

| Метод                | Итераций до сходимости | Время  | F1         |
|----------------------|------------------------|--------|------------|
| GD (`lr=0.1`)        | сотни                  | больше | сопоставим |
| Newton (`lr=0.5–1.0`)| **5–15**               | меньше | сопоставим |

**Вывод:** Ньютон сходится за единицы итераций (квадратичная сходимость), но каждая итерация дороже — `pinv(H)` имеет сложность $O(n^3)$. На 9 признаках Ньютон выигрывает и по итерациям, и по времени. На 10 000 признаках выиграл бы GD.

### Итоговое качество

Accuracy ~0.75–0.78, F1 ~0.65–0.70 — **типичный уровень для этого датасета** (литературный бенчмарк ~0.75–0.78 accuracy). Это честный результат, а не баг: данные шумные, классы несбалансированы (~65/35), а часть информации потеряна при заполнении пропусков.

## Выводы

1. **Препроцессинг важнее модели.** Обработка замаскированных пропусков и защита от leakage дают больше, чем перебор гиперпараметров.
2. **Learning rate — главный гиперпараметр GD.** Диапазон `[0.05, 0.1]` оптимален; слишком малый шаг ведёт к недообучению, слишком большой — к риску расходимости.
3. **Итерации быстро насыщают метрики.** 500–1000 достаточно; `early stopping` экономит время.
4. **Метод Ньютона — для маленьких задач.** Требует мало итераций, но они вычислительно дорогие; на малом числе признаков быстрее GD по времени.
5. **Порог 0.5 — не догма.** Для медицины логично снизить порог до `0.3`, чтобы повысить recall (меньше пропущенных больных) ценой снижения precision.
